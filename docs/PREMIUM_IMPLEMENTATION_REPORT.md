# AUTO UNIVERSE — реализация и проверка

Обновлено: 24 октября 2026 года. Изменения сделаны в существующем React / TypeScript / Vite frontend и FastAPI backend.

## Что реализовано

- Светлая основная тема, тёмная тема, общие цвета, поверхности, границы и состояния фокуса.
- Главная с автомобильной композицией, поиском по артикулу / названию / OEM, категориями, производителями и реальными подборками из каталога.
- Более плотная витрина по запросу пользователя: две карточки в ряд на телефоне, четыре на большом экране, крупная цена, скидка из данных товара, избранное над фотографией, заметная кнопка корзины.
- Меню каталога с категориями и брендами из API, закрытием через Escape, удержанием и возвратом фокуса.
- Поиск в шапке на мобильных экранах, быстрые фильтры наличия, скидки и категорий.
- URL-фильтры, сортировка, режим таблицы, пагинация, проверка диапазона цены. Черновик цены применяется по кнопке.
- Карточка товара с галереей, характеристиками, OEM-номерами, реальными отзывами и информацией о совместимости от backend.
- Корзина с изменением количества, удалением, проверкой остатков, состояниями ожидания и ошибок.
- Checkout с расчётом доставки через API, защитой от устаревшего ответа, повторным расчётом при ошибке, промокодами и бонусами.
- Только существующие способы оплаты: наличные при получении и банковский перевод. Имитация карточного / QR-платежа убрана.
- Аналитическая панель подключена к `/api/v1/admin/analytics/dashboard`. Имитация заказов и случайный рост показателей исключены из активного интерфейса.
- Добавлены категории продаж, количество деталей, новые регистрации, низкие остатки и последние заказы; сохранена проверка прав на сервере.
- Сохранены существующие авторизация JWT, регистрация, кабинет, гараж, история заказов, сравнение, поддержка, блог и административные операции.

## Достоверность данных

Нет придуманных рейтингов для товара без отзывов, процентов VIN-проверки, неподтверждённой доставки за несколько часов и фиктивной подписки в футере.

«Стоимость заказов» в аналитике — сумма неотменённых и невозвращённых заказов, а не сумма подтверждённых оплат. Фильтр 7 / 30 / 90 дней применяется к суммам, заказам, графику, категориям, новым регистрациям и лидерам продаж. Границы календарных дней — UTC. Остатки показываются на текущий момент, а не на историческую дату.

Шесть известных lifestyle-фотографий из `backend/app/seed.py` не являются фотографиями конкретных SKU. Для них предусмотрены иконки категорий с подписью «Фото уточняется»; реальные фотографии из каталога остаются без подмены. Для запуска магазина следует загрузить фотографии конкретных продаваемых товаров.

Попытка создать единый студийный атлас категорий встроенным ImageGen завершилась сетевой ошибкой. Несозданный файл не подключён к приложению. Альтернативный CLI-путь потребовал бы `OPENAI_API_KEY` и отдельного явного запроса пользователя; он не использовался.

## Выполненные проверки

- `npm.cmd run build`: TypeScript и production-сборка Vite проходят.
- `backend/.venv/Scripts/python.exe -m pytest -q --tb=short -p no:cacheprovider`: 59 тестов проходят. Единственное предупреждение — deprecation в Starlette / AnyIO.
- Добавлены регрессии аналитики: пустая база, исторические заказы, отмены, возвраты, согласованность графика и итогов, ограничения периода.
- Через работающий API на отдельной SQLite-базе `.runtime/premium-qa-20261023.db` проверены вход, каталог, корзина, расчёт доставки, оформление тестового заказа со статусом `pending`, очистка корзины и увеличение реального показателя заказов в аналитике.
- Предыдущая версия главной проверена в браузере на 320, 390, 430, 768, 1024, 1440 и 1920 px: переполнения страницы не было. Проверены обе темы, поиск SKU, применение цены в URL, мобильные фильтры и возврат фокуса через Escape.
- После доработки витрины 24 октября визуально просмотрены desktop-главная и desktop-каталог. Затем соединение с браузером прервалось. Полная повторная мобильная проверка нового двухколоночного варианта пока не подтверждена.
- Lighthouse не запускался; оценки Performance / Accessibility не заявляются.

## Ограничения перед запуском

- Внешний эквайринг и подтверждение онлайн-платежей отсутствуют в текущем backend.
- Инфраструктура ru / tg / en сохранена, но новые редакционные тексты преимущественно русские; полный перевод всех страниц остаётся отдельной задачей.
- Проверки выполнялись локально и на отдельной тестовой базе. Production-данные не мигрировались и не удалялись, сайт не публиковался.
- Для публикации нужны реальные фотографии SKU, подтверждённые контакты и условия магазина, повторная мобильная проверка, измерение производительности и настройки production-развёртывания.

## Локальный запуск

Обычное приложение:

```powershell
cd backend
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

```powershell
cd frontend
npm.cmd run dev -- --host 127.0.0.1
```

Frontend обращается к FastAPI через `/api/v1` и Vite proxy. Необязательная переменная `API_PROXY_TARGET` позволяет выбрать отдельный локальный backend для QA.
